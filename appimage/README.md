# AppImage packaging — Umber

v1 AppImage track for the requirements §10 distribution row. Status:
source files land here; the AppImage itself is produced by CI
(`.github/workflows/packaging.yml`, `appimage` job) or a human run —
not by this kill (no cargo / no downloads in the claw).

## Files (AppDir sources, not the AppDir itself)

| File | Role in the staged AppDir |
|---|---|
| `org.umber.Umber.desktop` | `AppDir/org.umber.Umber.desktop` (root per the AppImage spec) + `AppDir/usr/share/applications/` |
| `umber.svg` | `AppDir/umber.svg` (root icon) + `AppDir/usr/share/icons/hicolor/scalable/apps/` |
| `org.umber.Umber.metainfo.xml` | `AppDir/usr/share/metainfo/` (appimagetool validates it at pack time) |
| `README.md` | this file (build docs; NOT staged into the AppDir) |

The staged tree the CI job assembles (before linuxdeploy fills in
shared-library dependencies):

```text
AppDir/
  org.umber.Umber.desktop          # from appimage/
  umber.svg                        # from appimage/
  AppRun                           # GENERATED by linuxdeploy (see below)
  usr/bin/umber                    # cargo --locked build --release -p umber-app
  usr/bin/LICENSE                  # GPL-3.0-or-later: the license travels with the binary
  usr/share/applications/org.umber.Umber.desktop
  usr/share/icons/hicolor/scalable/apps/umber.svg
  usr/share/metainfo/org.umber.Umber.metainfo.xml
```

## Judgment calls (v1 boundaries)

- **No committed build script.** The repo wall forbids bash scripts, so
  there is deliberately no `build-appimage.sh`: the build steps live as
  auditable `run:` steps in `.github/workflows/packaging.yml`. The files
  here are the honest inputs; the workflow is the honest procedure.
- **No committed `AppRun`.** linuxdeploy generates `AppRun` from
  `--executable`/`--desktop-file`/`--icon-file`; hand-writing one would
  duplicate (and drift from) the generator. Same reason there is no
  committed AppDir skeleton: the tree above is documentation, the CI job
  stages it.
- **linuxdeploy + appimagetool path (not hand-rolled `ldd` bundling).**
  Hand-copying `.so` files is fragile against the wgpu/winit closure;
  linuxdeploy resolves and copies it, appimagetool packs and lints.
  Pins (verified 2026-10-12, recorded for the gate to re-check):
  appimagetool **1.9.1**
  (`https://github.com/AppImage/appimagetool/releases/download/1.9.1/appimagetool-x86_64.AppImage`);
  linuxdeploy rolling **continuous**
  (`https://github.com/linuxdeploy/linuxdeploy/releases/download/continuous/linuxdeploy-x86_64.AppImage` —
  linuxdeploy publishes no stable versioned release, so continuous is the
  only pin available; the gate re-verifies the URL).
- **Built on ubuntu-22.04.** The oldest CI image = the lowest glibc floor
  (2.35), so the AppImage runs on newer distros. Building on
  ubuntu-latest would silently raise the floor — do not "upgrade" the
  runner without recording the new floor here.
- **The Vulkan loader is NEVER bundled.** Same rule as the installers
  design doc: libvulkan and the Mesa drivers are system-provided. If
  linuxdeploy pulls `libvulkan.so*` into the AppDir, that is a packaging
  bug: exclude it and re-run. The CI job asserts its absence.
- **Icon is a placeholder composition.** `umber.svg` traces the lucide
  `paintbrush.svg` glyph (from `assets/icons/`, ISC set) in amber
  (`#e8a33d`) on a dark pro-theme tile (`#1a1d24`). It exists so
  desktop/AppStream/appimagetool validation passes — it is NOT the Umber
  brand mark. The real mark + multi-resolution PNG exports are deferred.
- **Metainfo duplicated, not shared, with `flatpak/`.** The AppDir and
  the Flatpak module each need their own file-source copy today; a
  single-source layout (one canonical file, copied at build time) is the
  named follow-up. If you edit one copy, edit both (CI diffs them).
- **No `MimeType=` in the desktop file** (same reason as Flatpak: no
  shared-mime-info definition ships v1).
- **Only the `umber` binary ships v1.** `umber-cli` stays in the
  cargo-dist archives; bundling it into the desktop AppImage is a
  follow-up, not an oversight.

## Runtime dependencies (for the manifest record)

Inside the AppImage: the `umber` binary + its non-system shared-library
closure (bundled by linuxdeploy: X11/Wayland client libs, xkbcommon,
fontconfig, etc.). Outside (host-provided, never bundled): the Vulkan
loader + ICD drivers, Mesa, GPU kernel drivers, FUSE (only needed to run
type-2 AppImages without extraction — `--appimage-extract-and-run` is the
FUSE-less fallback). wasmtime/Cranelift is statically linked — no runtime
`.so` concern.

## Build locally (human run — the claw cannot)

```sh
cargo --locked build --release -p umber-app
# stage the tree above into AppDir/, then:
./linuxdeploy-x86_64.AppImage --appdir AppDir \
  --executable target/release/umber \
  --desktop-file appimage/org.umber.Umber.desktop \
  --icon-file appimage/umber.svg \
  --output appimage
```
