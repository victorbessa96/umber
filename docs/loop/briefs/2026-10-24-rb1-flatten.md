## The honest reshape (found by derivation, BEFORE the brief)

The census assumed Painter's GROUP → but Umber does not model
folder membership AT ALL: `layers_panel.rs:465`'s own judgment
call ("Group: folder membership is not modeled") — the Ctrl+G
gesture gathers the selection contiguously; no folder kind exists
(`SnapshotLayerKind` = Paint/Fill/Material only,
paint_state.rs:849-856). **The flatten is therefore a
SELECTED-LAYERS flatten**, which still delivers the
destructive-when-wanted workflow the census names: select N
layers → one baked paint layer with real pixels per channel, the
sources removed. Folders + the folder-flatten variant come later
(they need the folder kind first — a separate, larger kill).

## The anchors (verified live)

- **The composite read**: `PaintState::read_composite(tile,
  channel)` (paint_state.rs:4008) — the composited readback; the
  range machinery = the snapshot builder's prefix reads
  (`read_anchor_prefix` :4045, the CPU oracle m11) + the
  composite-cache class. The flatten reads the SELECTED range's
  composite per tile × channel — the same class of read the
  export path does.
- **The publish**: `PaintState::publish_plane` (:3532) with a
  `PlaneOwner::Layer(new_id)` — the baked pixels become the new
  layer's own planes.
- **The command family**: `LayerCommand` (umber-core/src/
  layers.rs:1458: Add/Remove/Reorder/SetOpacity/SetVisible/
  SetBlendMode/Rename/SetFill/SetMaterial... each with apply/
  revert + the captured old state).
- **The UI row**: the layers panel's context menu (the gestures'
  home; `LayerGesture` enum, layers_panel.rs:550-class) + the
  confirm gate (destructive = confirm, GUI plan rule 8; the
  Delete confirm's precedent at :634).
- **The undo's deep half** (the kill's core): the removed
  sources' planes + the new layer's planes must round-trip
  through undo. The precedents: the retouch history's plane
  captures, the persistence plane round-trip, the
  `resize_set`-class clear semantics. The flatten command's
  `revert` must restore the removed layers WITH their planes
  and remove the new layer + its planes — a compound journal
  entry (one undo step, the Drag-Dot release-dab precedent for
  one-step compounds).

## The kill's shape

1. **Engine** `PaintState::flatten_layers(&mut self, ids: &[u64])
   -> Option<u64>` in umber-paint:
   - The ids must be a valid stack selection (top-to-bottom
     contiguous NOT required — the composite is order-sensitive,
     the stack's own order defines it).
   - Read the range's composite per tile × the channels present
     (the read_composite class over the selected range's planes).
   - `LayerCommand::Add` a Paint layer at the TOPMOST selected
     position (the gathered shape, the Group gesture's own
     precedent), `publish_plane` the baked bytes per channel.
   - Remove the sources (Remove × N, captured).
   - Return the new id.
2. **The command**: a `Flatten` journal entry (or the compound of
   Add + Removes with the plane capture) — ONE undo step; `revert`
   restores the removed layers + their planes and drops the new
   layer + its planes. Name the journal family it rides in the
   implementation (the retouch-history class vs the
   Document::run command family — read both homes at dispatch and
   follow the one the layers already use).
3. **The UI**: the layers panel's context menu gains "Flatten N
   layers" (the selection-count string; i18n keys ADDABLE — the
   lock is lifted) + the confirm dialog (the Delete confirm's
   shape, listing the names — the layers_panel.rs:472
   precedent's body pattern).
4. **Tests** (umber-paint's suite):
   - Two paint layers with strokes → flatten → the new layer's
     plane bytes equal the composite read (the byte-exact pin).
   - Undo → the sources restore WITH their planes (strokes
     re-read byte-exact); redo → the flatten re-applies.
   - The mixed selection (Paint + Fill): the fill's contribution
     bakes in (the Fill precedent: Passthrough composites as
     Normal).
   - A mask on a source: the mask's effect is IN the bake (the
     composite honors it); the mask layer itself is NOT consumed
     unless selected (Painter's rule; name the choice in the
     report).
   - The empty/one-layer selection: refuse (status-bar reason,
     the availability precedent).
