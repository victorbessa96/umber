## Built

- `widgets/notices.rs` (new):
  - `NoticeLevel {Info, Warning, Error}` with `stroke_color()`:
    `theme::hover()` / `palette::WARN` / `palette::ERROR`.
  - `Notice { id, level, text, sticky, shown_at: Option<f64> }` +
    `remaining(now)`.
  - `Notices { items, next_id }`: `post`, `post_sticky` (both return the id),
    `dismiss(id) -> bool`, `is_empty`.
  - Cap `MAX_VISIBLE = 3`: posting over the cap drops the oldest non-sticky
    notice, or the oldest overall when every notice is sticky.
  - Pure timing: `stamp(now)` sets `shown_at` the first time a notice is
    drawn. `expire(now, hovered) -> bool`: while hovered, every shown timer
    resets to `now` and nothing expires. Otherwise non-sticky notices past
    `AUTO_HIDE_SECS = 6.0` are dropped. `next_deadline(now)` returns the
    soonest remaining time, clamped at 0.
  - `show(ctx)`: `Area::new(Id::new("umber-notices"))`, `Order::Foreground`,
    anchored `RIGHT_BOTTOM` at `(-16, -36)`. Each notice is one
    `Frame::NONE` card: `raised()` fill, a 1px stroke in the level color,
    the popup shadow, and a frameless muted × button. Calls
    `request_repaint()` once on the frame a card expires, then
    `request_repaint_after(next_deadline)`. No continuous repaint.
- `widgets/mod.rs`: `pub mod notices` + re-exports `Notice, NoticeLevel, Notices`.
- `lib.rs`: module doc line + crate-root re-export of the three types.

## Judgment calls

- Hover is read against the Area's rect from the previous frame
  (`memory.area_rect`), so the timers can run before the stack is drawn.
  The alternative was reading hover from this frame's response after
  drawing, which leaves a frame where an expired card has already been
  drawn. One frame of hover lag is not visible.
- Hover reset skips notices that have not been shown yet. Those have no
  timer, and stamping them here would be wrong.
- If every notice is sticky, the cap drops the oldest sticky one. The
  alternative was to let the stack grow past 3. The spec says "max 3", so
  the cap holds.
- Text is given already translated: callers pass `tr()` output, since
  umber-gui has no i18n. The research row stores an English template + args
  and translates at draw time, so notices follow a language change. That
  part is deferred (below).
- I kept `next_id` private: ids are unique and increasing, and `items` is
  public for reading. Plain `pub` struct fields were the alternative.
