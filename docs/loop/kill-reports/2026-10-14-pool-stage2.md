## 2. Judgment calls (also written into the module docs)

1. **Census name `planes_present() -> Vec<(PlaneOwner, u16, String)>`** —
   the doc never names the save census; this mirrors `tiles_present()` /
   `channels_present()`. Owned `Vec` so no session borrow crosses the
   `&mut` readback/commit calls (E0502 by construction).
2. **Commit accessors `plane_committed` /
   `mark_plane_committed(owner, tile, &str, PathBuf, blake3::Hash)`** — the
   doc names the `Plane.committed` field (stage-1b-owned); main.rs needs
   read + write across the crate boundary, so accessor methods are assumed
   rather than field access. Hash is `Copy`; dirs are stored raw and
   canonicalized at compare time, per §6.2.
3. **`read_plane` / `publish_plane` / `clear_layer_planes` / `PlaneOwner`
   shapes** taken literally from the doc (§1.2, §5.1, §6.3): `read_plane`
   `&mut self` (drains, like `read_tile`), `publish_plane` returning
   `Result<(), PaintRefusal>`, `PlaneOwner::{Base, Layer(u64)}` with the
   doc's full derive list (incl. `Ord`, which the `BTreeMap` census key
   needs for byte-deterministic manifests).
4. **`PaintTileSkip` unchanged** — still `(tile, channel)`-keyed; the owner
   rides the warn line. Two owners skipping on one `(tile, channel)` would
   yield twin records; accepted as a diagnostic edge (no behavior impact).
5. **No requirements row marked** — stage 2 completes no user-visible row
   (no UI creates a plane yet; rows :120/:124 close in stage 4 with the
   merge-story doc delta). Per hard rule 9, nothing to mark.
6. **`prune_empty_layer_dirs` skips (never counts) fault-injection steps**
   — removing an empty dir is crash-safe either way, and no fault test
   covers the `layers/` depth.
