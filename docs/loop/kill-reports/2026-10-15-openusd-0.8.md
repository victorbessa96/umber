# Kill report — openusd 0.7.0 → 0.8.0 (wave-openusd-0.8)

Date: 2026-10-15. Author: dragon. Lock: `openusd-0.8` over `Cargo.toml`,
`Cargo.lock`, `crates/umber-mesh/src/usdc.rs`,
`crates/umber-mesh/tests/panic_hunt_mesh.rs`, the new
`crates/umber-mesh/tests/assets/usdc_tri_openusd_0_7_0.usdc`, `SECURITY.md`,
this report. Source: the upstream-reports kill
(`docs/upstream/openusd-0.7.0.md`): all six openusd findings, including the
#19 allocation ABORT, are fixed in 0.8.0 (mxpv/openusd#138).

## Built

- `Cargo.toml`: `openusd = "0.8.0"`; `Cargo.lock` via `cargo update -p
  openusd --precise 0.8.0` (only openusd moved).
- `usdc.rs`: `CrateData::open` takes `impl Into<AssetBuffer>` in 0.8, so
  the `Cursor` wrapper goes — the owned `Vec<u8>` passes straight in. The
  module doc's error contract now says the reader's aborts are fixed
  upstream and the panic boundary stays as defence in depth.
- `panic_hunt_mesh.rs`:
  - **Frozen bytes.** 0.8.0's writer emits the fixture layer in 866 bytes,
    not 869, which moved every mapped flip offset (the 869-byte length pin
    fired, 7 reproducers red on first run — the pin working). The
    reproducers exist to feed the SAME corruptions to the new reader, so
    the 0.7.0-written bytes are now a committed asset
    (`usdc_tri_openusd_0_7_0.usdc`, 869 bytes, sha256 `17fc9b1b4fbf3283…`,
    regenerated in a throwaway crate pinned `openusd = "=0.7.0"`), read by
    `usdc_frozen_0_7_0()`. `usdc_flip` and both mutation hunts (usdc,
    usdz) seed from it, so the `flip@104` / `mutate seed=10` case names
    keep naming the same bytes.
  - `USDC_ABORTS` / `USDZ_ABORTS` emptied: the 25 + 15 cases the hunts
    used to SKIP as process-killing now run and must come back typed.
  - `bug_usdc_huge_count_allocation_aborts` un-ignored (child-process pin
    stays). The six `bug_openusd_*` comments say FIXED in 0.8.0.
- `SECURITY.md` mesh row: the abort class is closed, and how it is pinned.

## Evidence

`cargo test -p umber-mesh` (pre-battery): lib 90, panic hunt 32 passed /
1 ignored (the triage tool). Hunt lines: `[usdc] ok=24 err=438
skipped-abort=0 panics=0`, `[usdz] ok=8 err=661 skipped-abort=0
panics=0` — before the bump the same hunts skipped 25 and 15 cases.

## Judgment calls

1. **Freeze the bytes rather than re-map the offsets to 0.8.0's output.**
   Re-mapping would test 0.8.0 against corruptions of its own output —
   not the corruptions that broke 0.7.0. Frozen bytes are a true
   regression test of the fix, and immune to the next writer change.
2. **Keep `load()`'s `catch_unwind`.** The dependency is fixed, not
   proven panic-free; the boundary costs nothing on the happy path.

## Unverified

- 0.8.0's other API changes beyond `CrateData::open` are untouched by
  Umber's call sites (the battery's compile is the check), and its
  WRITER is only exercised by the test fixtures.
