## What landed (claw-authored, reviewed from source — not re-verified by run)

`paint_state.rs`:

- `TileTargets { base_color: PaintThread, channels: BTreeMap<String,
  PaintThread> }` (`:393-396`); `targets: BTreeMap<u16, TileTargets>`.
  `threads_mut` (`:403`) walks base + every channel so
  `process_pending` and `resize_set` never leave a materialized channel
  undrained or stale-sized.
- `BASE_COLOR_CHANNEL = "baseColor"` (`:355`): routing to it resolves to
  the `base_color` field and never allocates a `channels` entry.
- `active_channel` (`:697`) / `set_active_channel` (`:706`, no-op
  mid-stroke) / `stroke_channel` snapshot at `begin_stroke` (`:833`).
  Staging routes to the snapshot (`:1939-1942`); the capture snapshots
  before-bytes per (tile, channel) (`:1966-2006`).
- `ensure_channel` (`:1674`), `publish_fill_channel` (`:1280`),
  `read_channel_tile` (`:2132`, never materializes),
  `channels_present` (`:1537`, the save census; baseColor implicit).
- `record_paint_capture` builds `StrokeTile`s carrying the channel
  (`:1378-1388`); undo/redo flush through `target_of_mut(tile,
  &channel)` (`:1215-1231`).

`main.rs`:

- `paint_channel_tile_path` (`:809`): flat `paint/tile-<N>.png` for
  baseColor (IDENTICAL to `paint_tile_path` — the v2 layout
  byte-for-byte), `paint/<channel>/tile-<N>.png` otherwise.
- `paint_sidecar_name` (`:828`) / `parse_paint_sidecar_name` (`:844`):
  the channel rides in the manifest NAME field, NOT a new column (see
  "Codec" below).
- `save_paint_tiles`/`commit_paint_tiles` (`:1443-1540`) stages
  baseColor + every `channels_present` entry; `collect_paint_tiles`
  (`:1582`) + `load_paint_tiles_reported` (`:1619-1770`) restore via
  `publish_fill` / `publish_fill_channel` (`:1755-1759`).

`retouch.rs`: the undo key is (tile, channel) — `StrokeTile.channel`
(`:331-337`), `TileRegion.channel` (`:470-479`), `can_merge` matches on
both (`:370-391`; a height stroke never coalesces with a baseColor
entry), `merge_stroke` keys regions by `(u16, String)` (`:397-401`).
Retouch tools themselves stay baseColor-only in v1 (`:290-294`).

Deliberate deviation from the design sketch, already documented in the
tree (`main.rs:793-801`): baseColor does NOT move to `paint/baseColor/`
— it stays flat, so every v2 project and every single-channel session
keeps its exact path (zero-churn diff). `collect_paint_tiles` notes a
literal `paint/baseColor/` subdir would WIN over a same-tile flat file
(forward-compat, never written today).

## Test gates (this session — 4 tests, all exact-value, all must-fail-able)

1. `paint_state.rs:3740`
   `height_channel_is_isolated_from_base_color_with_per_channel_undo`
   (design gate 1). `ensure_channel(1001, "height")`,
   `publish_fill_channel(1001, "height", 512, 512, pattern)`; asserts
   height reads back byte-identical AND baseColor is all-zero AND
   `read_channel_tile(1001, "roughness")` is `None` (reads never
   materialize — census still `["height"]`). Then a REAL paint stroke
   with `set_active_channel("height")` (fills record no undo entry —
   asserted via `!can_undo_stroke()` — so the undo half rides the
   stroke path, which records one (tile, channel)-keyed entry):
   undo restores the fill byte-exact with baseColor still zero; redo
   replays the stroke bytes.
   Derivation: pattern texel `(x,y,c)` = `(x*31 + y*17 + c*71 + 5)
   mod 251`; seed 5 pins (0,0) = `[5, 76, 147, 218]`, (1,0).r = 36.
   The stroke-vs-pattern `assert_ne` is derived, not hoped: pattern
   bytes are all < 251 (mod 251) while the default brush
   (`[0.85, 0.2, 0.1, 1.0]`, `umber-brush/src/dab_adapter.rs:66`)
   stamps full-coverage texels at alpha 255 — a value the pattern can
   never hold — so at least one byte must differ.
2. `paint_state.rs:3852`
   `channel_targets_materialize_lazily_per_routed_channel` (design gate
   2). Census = `channels_present(1001).len() + 1` (baseColor
   implicit). Fresh = 1; after routing one of five known names = 2;
   re-route and `ensure_channel(baseColor)` stay at 2 (reserved name
   never allocates); the four unrouted names read `None`, and reads
   leave the census at 2; `tile_count` stays 1 throughout (routing a
   channel never spawns a tile).
3. `main.rs:2659`
   `two_channels_round_trip_byte_identical_per_channel` (design gate
   3a). 512² session (sizes match the target — a 512 publish into a
   4096 target would land a 512 region, not the pattern), base seed 3
   + height seed 77 through the REAL `save_paint_tiles` path.
   Asserts `saved == 2`, flat `paint/tile-1001.png` exists (the v2
   layout byte-for-byte), `paint/height/tile-1001.png` exists, the
   manifest names exactly `tile-1001.png` + `height/tile-1001.png`,
   no `manifest.pending` remains; fresh `PaintState::new` reopens
   `restored == 2`, `channels_present == ["height"]`, both channels
   byte-identical at 512².
   Derivation: seed 3 pins (0,0) = `[3, 74, 145, 216]`, seed 77 =
   `[77, 148, 219, 39]` (`(213+77) % 251 = 39`) — same formula as the
   two-set template test.
4. `main.rs:2758` `v2_flat_manifest_loads_all_base_color` (design gate
   3b, migration). Hand-written codec pins (see "Codec" for the
   verified quotes): a 5-field flat line parses (64-zero hash is a
   valid `AssetRef` shape per `umber-core/src/assets.rs:57-68`); a
   6-field line refuses the WHOLE manifest; `parse_paint_sidecar_name`
   pins flat→baseColor, `height/…`→height, `baseColor/…`→baseColor
   (the collect-wins rule), and 9 rejections (empty, trailing slash,
   empty/`..`/backslash channels, bad tile, wrong ext). End to end: a
   baseColor-only save through the real path writes no channel dir,
   every tile manifest entry parses to flat baseColor, and a fresh
   session restores 1 tile byte-identical with `channels_present`
   empty (migration materializes nothing).

## Codec's exact migration behavior (verified against source, quoted)

`parse_paint_commit` (`main.rs:1136-1165`) destructures

```rust
let fields: Vec<&str> = line.split(' ').collect();
let [name, hash, ext, size, temp] = fields.as_slice() else {
    return None;
};
```

— an EXACT 5-field array; any other arity refuses the whole manifest.
There is no channel column in either version, so there is nothing to
tolerate: the channel rides in `name` (`paint_sidecar_name`), and
`parse_paint_sidecar_name` maps a bare `tile-<N>.png` to
`(BASE_COLOR_CHANNEL, tile)`. A v2 manifest (flat names only) therefore
loads all-baseColor BY CONSTRUCTION, restored through `publish_fill`
(`main.rs:1755-1756`).

Stale-doc note: the design's "Migration" paragraph
(`per-channel-tile-pool-design.md:110-113`) says "the codec's
unknown-column policy already tolerates this — verify at
implementation". Implementation shows there IS no unknown-column
policy — a 6th column is a hard `None` (pinned by test 4 above). The
migration works anyway, via the name field, which is strictly better
(old binaries never see a shape they reject — they just never write
channel names). The design doc should be amended to say that; not done
here (docs/specs is outside this kill's locked surface only insofar as
requirements.md is — the doc edit is left for the dragon).
