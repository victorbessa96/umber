# Kill report: icons-a11y (g7-accesskit-sweep deferred item)

- Authorship: dragon (solo, host-down pass).
- Kill-lock `wgui2-icons-a11y`: `crates/umber-gui/src/icons.rs`.
- Closes the umber-gui a11y sweep's Deferred item: `icon_button` is
  painter-drawn and used app-wide, so one edit here gives every icon
  button in Umber its accesskit identity.

## Built

- `icon_button_enabled` (the fn behind `icon_button` and every
  `_enabled` call site): `response.widget_info(|| WidgetInfo::labeled(
  WidgetType::Button, enabled, name))` — the Button role with the
  icon's own name as the label, respecting the `enabled` flag.
- Test: `an_icon_button_reports_a_button_role_to_accesskit` (kittest:
  `get_by_role_and_label(Role::Button, "paintbrush")` over an
  `IconAtlas::empty()` harness — the get_ panics on miss).

## Judgment calls

- **The icon name as the label** (not a new signature param): changing
  the signature would touch every caller across lock-held files for a
  label screen readers only announce as fallback — the callers'
  tooltips already carry the localized description, and `on_hover_text`
  does NOT feed accesskit (verified against egui 0.36.2 response.rs:727
  — it only draws the tooltip). The stable icon id ("paintbrush",
  "eraser") is a better label than nothing, and the ROLE is the primary
  signal. A `icon_button_labeled` variant for future localized-label
  call sites is named as the follow-up if a panel ever needs per-locale
  a11y labels on icons.
- **`enabled` threaded into WidgetInfo::labeled** — a disabled icon
  button reports `enabled: false`, which ATs surface as unavailable;
  the disabled click-guard behavior is unchanged.
