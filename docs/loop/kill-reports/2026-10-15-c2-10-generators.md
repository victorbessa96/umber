# Kill report: C2-10, smart-material generators bind to the baked maps

Date: 2026-10-15. Author: dragon. Lock: `c2-10-generators` over
`crates/umber-app/src/{document,bakes_panel,main}.rs`, the user guide and
this report.

## The design call

Snapshot, not a live link. A fill layer's source is `FillSource::GraphImage`,
a pixel snapshot; the baked maps are files the Bakes panel writes. Applying a
smart material copies the newest bake of each generator's `map_name` into its
fill, as one undoable `set_fill`. Re-applying after a rebake picks up the new
bake. A live fill↔bake link would need a new `FillSource` variant and project
format work; it stays possible later.

## Built

- `BakesPanel::latest_map(name)`: the newest tile-1001 file per map, keyed by
  the `.umbersmart` vocabulary (`AO`, `curvature`, `position`, `normal`,
  `height`, ...; case-insensitive).
- `document::bind_smart_generators(doc, material, ids, map)`: each
  `mesh_map_generator` fill gets a `GraphImage` of `map(map_name)`. Unbaked
  maps are returned for the log, and their fills stay plain. A template/ids
  mismatch binds nothing.
- `LayersUiOutcome.smart_applied` carries the shelf's apply to the shell,
  which binds from the Bakes panel (reading each PNG; a read error logs and
  counts as missing).
- The user guide covers the shelf: bake first, then apply.

## Tests

- `smart_generators_bind_baked_maps_as_undoable_fill_snapshots`: with only
  AO baked, "Wood grain" (AO) binds to the AO bytes and "Paint coat"
  (position) is reported missing. The bind is one history entry, and undo
  restores the unbound fill. **Mutation check:** every generator reading AO
  fails the test.
- The Bake-from-high GPU test now also pins `latest_map` (height, normal by
  name, unbaked AO is None, an unknown name is None).
- Gate 1: umber-app 528. fmt and clippy clean.

## Open

- Smart masks (the `.umbermask` half of C2-10).
- `noise_perlin` and other self-contained generators (empty `map_name`)
  stay unbound; they need the graph evaluator, not a bake.
