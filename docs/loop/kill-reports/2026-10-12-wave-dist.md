## Judgment calls (also in flatpak/README.md + appimage/README.md)

1. `org.freedesktop.Platform.Vulkan` does not exist — verified against
   the flatpak-docs runtime/extension list during the kill. Mesa/Vulkan
   drivers ship via `org.freedesktop.Platform.GL.default`, auto-pulled by
   `--device=dri`. The manifest uses `--device=dri` and no Vulkan
   extension. Load-bearing correction, recorded in three places.
2. Buildsystem `simple` + direct cargo (no meson/cmake wrapper);
   `cargo --locked` for dep reproducibility; build-time network accepted
   (Flathub-vendoring deferred, recorded).
3. Rust via the Flathub rust-stable SDK extension, NOT the repo-pinned
   1.97.0 — sound because `rust-version = "1.85"` is the floor; drift
   acknowledged in the README.
4. No extra SDK modules v1 — the 24.08 SDK ships the X11/Wayland dev
   libs winit 0.30.13 needs; CI failure names any missing module.
5. Git source tracks `master` until the first release tag (Bessa's call).
6. No committed AppImage build script (repo wall) and no committed AppRun
   (linuxdeploy generates it) — workflow `run:` steps are the procedure.
7. linuxdeploy has no stable versioned release → continuous URL is the
   only pin; appimagetool pinned 1.9.1.
8. AppImage builds on ubuntu-22.04 (glibc 2.35 floor); the runner must
   not be "upgraded" without recording the new floor.
9. Icons/metainfo honestly marked placeholder/development; no invented
   screenshot URLs, no MimeType claims, `umber-cli` stays out of the
   desktop AppImage v1.
