- Entry: `import_psd_bytes(bytes, file_name)` (read + flatten),

  is unit-testable with hand-built structs, no files), `map_read_error`,

  `empty_state::is_mesh_file`).
- Path A: `Psd::canvas` (else `image_data`) imported verbatim when
  present with `len == w*h*4`, nonzero dims, under the frame cap.
- Path B: file-order bottom-to-top walk; pixel layers via Porter-Duff
  `over` with coverage `alpha × mask × opacity-chain`; group opacity as
  a group-wide alpha multiply (accumulated `chain`); simple grayscale
  raster masks at 1:1 texel mapping with own-origin placement
  (full-document masks over cropped layers work) + `default_color`
  outside + `density` multiply; normal/multiply/screen exact through
  `umber_core::BlendMode::blend_channel`; everything else flattened as
  normal + a substitution line. Hidden/empty/mismatched records skip
  loudly; blend-if/knockout/vector-mask/fill-opacity/clipping each get
  their line; out-of-canvas pixels clip loudly, never wrap.
- Errors (never panics): `Read` (verbatim reader message),
  `UnsupportedColorMode{mode}` (CMYK/Lab/Multichannel/Duotone-declaring
  files — the reader's composite arm rejects them with
  `StrictViolation`, so they are rejected, never mangled),
  `InvalidDimensions` (non-finite/zero/fractional/`>8192`/overflow/`>256
  MiB`), `NoPixelTruth` (no composite + zero composited layers, with the
  census in the detail).
- `PsdImportReport` (counts + `substitutions`/`masks_applied`/
  `masks_skipped`/`conversions`/`notes` + deterministic `summary()` whose
  last line always names the v2 layer-mapping deferral) and
  `PsdImportState` (`pending`/`skipped`/`applied`/`session_set_name`/
  `last_report`/`status`, `ingest_name`/`ingest_paths`/`scan_dir`/
  `import_one`, mirroring `mesh_map_import`'s method shapes).
- `PSD_TARGET_CHANNEL` (`"baseColor"`), `PSD_EXTENSIONS`, `MAX_PSD_SIDE`
  (8192), `MAX_PSD_BYTES` (256 MiB = exactly one 8K RGBA8 frame).

## 2. Judgment calls (also written into the module docs)

1. **ag-psd 0.3.0 API read from source, not memory.** `Psd::canvas`
   holds the composite under default options; layer/mask canvases are
   RGBA8 clones; layer opacity and mask density are `0.0..=1.0`;
   density present only for non-default mask params; `children`
   preserves file order; folders are `Layer{children: Some}` from
   section dividers. `write_psd` returns `Vec<u8>` (the claw-artifact
   README's `&mut impl Write` note is stale; the export code is truth).
2. **z-order = file order bottom-to-top** (Adobe layer-record
   convention; the crate never states it). Pinned by test 1 for
   self-consistency; every report carries the assumption line so a
   flipped real file is diagnosable.
3. **Blend subset is exactly normal/multiply/screen** per the brief —
   even though `umber-core` carries Darken/Subtract/Difference/… Wider
   math is v2's to claim mode by mode. Checked `umber-color` first per
   the brief: it owns display transforms + CM flags only, no blend math.
4. **Bytes blended as given** (matches Photoshop legacy gamma-space
   compositing better than linearizing would); `umber-color` stays
   downstream.
5. **Conversions are reader-side and reported**: 16/32-bit top-byte
   downshift, grayscale replication, palette expansion, naive CMYK-layer
   inversion. No umber-color CMYK path exists to route through — the
   rejection names that instead of pretending.
6. **Masks**: user mask wins over real (noted when both); feather ≠ 0
   or non-finite → skip; disabled → skip; no-raster + default color →
   uniform multiplier; geometry handled by origin mapping (no
   resampling ever); mask channel sampled from R (reader decodes mask
   channels into R).
7. **Groups**: no isolation — passthrough-with-multiply for every
   folder blend (Normal included, reported); nested chains multiply.
   Approximation of true isolation for translucent stacks; opaque stacks
   exact. Reported per group.
8. **Report strings are document data, not `tr()` keys** (same rule as
   `"Imported <map>"`): identical across locales, completeness test
   green with no `.ftl` delta. Panel chrome i18n is the merge's.
9. **Clipping, blend-if, knockout, vector masks, fill-opacity**: the
   first four deviate-and-report; fill-opacity folds in (no effects
   exist to distinguish it from opacity) + note.
10. **Dims cap 8192/256 MiB** (8K ceiling matches the export row);
    fractional dims refused (Photoshop rects are integral).
11. **Test-value margins**: every rounded expectation sits ≥ 0.1 from a
    `.5` boundary under the exact code formula `b*sa + d*(1-sa)`,
    `(v*255).round()` — f32 error (~1e-5) cannot flip any assert. The
    one exact-midpoint case (test 4, 127.5) relies on `round()` =
    half-away-from-zero, which is deterministic, not platform behavior.
12. **No vendored ag-psd test PSDs exist** (src-tree is source only;
    upstream fixtures not shipped) — path A is covered by our own
    writer's round trip (test 13), path B by hand-built structs.
13. **`mod psd_import;` deliberately absent**: adding it is a `main.rs`
    edit owned by the spp claw this wave. The file compiles the moment
    the merge adds the line (alphabetical slot: between `postfx_panel`
    and `retouch`).
