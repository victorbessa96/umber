# Kill report: C2-30, Windows pen pressure needs no `winink` feature

Date: 2026-10-15. Author: dragon. Lock: `c2-30-winink` over the user
guide, the C2 audit, the queue and this report. Docs only: no code
changed, so no build was needed.

## The approved plan, and why it changed

Bessa approved "Windows Ink default-on". Before writing the Cargo change,
I traced what `stylus/winink` would add. It adds nothing a Windows user
can feel; the default build already has pressure.

## The trace (registry sources, versions from Cargo.lock)

1. **winit 0.30.13**, `platform_impl/windows/event_loop.rs:1985`: the
   window procedure handles `WM_POINTERDOWN | WM_POINTERUPDATE |
   WM_POINTERUP`. For `PT_PEN` (:2087) it calls `GetPointerPenInfo` and
   `normalize_pointer_pressure` (:994: `1..=1024 → Force::Normalized(p /
   1024)`). It sends `WindowEvent::Touch { force }`.
2. **egui-winit 0.36**, `on_touch`: pushes `egui::Event::Touch { force:
   Some(normalized) }` and emulates the pointer: Started presses the
   left button, Moved moves the cursor, Ended releases.
3. **Umber**, `viewport.rs:~503`: reads `egui::Event::Touch { force }`
   inside the viewport rect and feeds it to
   `stylus_input::resolve_pressure` as `touch_force`.

So a Windows pen's pressure reaches every stroke in the default build.

## What `stylus/winink` is

A passive `WM_POINTER` decoder (`PenState::decode`) with no window hook.
`stylus::open_system_stream` returns `None` on Windows in every
configuration (lib.rs: "Windows Ink stays the named follow-up — its
passive decode exists but has no window hook yet"). Turning the feature
on by default would compile dead code into every Windows release and
change nothing.

## What winit does NOT give, and what winink would be FOR

Tilt, twist (rotation), the barrel button and the eraser end: `Touch`
carries position and force only. Those are winink's real future value.
They need a `WndProc` subclass in the app (the stylus module docs' "Wave
2"), which is new work, not a feature flag.

## Changes

- User guide: the stale "Windows Ink is a build option" line is replaced
  with the truth (pressure works in the default build; tilt is the gap).
- The C2-30 audit row and queue row are closed with this finding.
- No Cargo change. The CI winink test step stays: it is still the decoder
  crate's only test executor.

## Not verified

No hardware run. A real Windows pen check (pressure ramps a stroke's
width) stays on the release checklist's manual list. The trace is source
reading, not observation.
