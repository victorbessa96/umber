# Kill report: C2-20 panic-hunt the uncovered parse seams

Date: 2026-10-15. Author: dragon. Lock: `c2-20-panic-hunt` over
`crates/umber-app/tests/panic_hunt.rs`, `crates/umber-cli/tests/agent_panic_hunt.rs`
and this report. Source: `docs/loop/audit-2026-10-15-c2.md` row 20.

## Built

The first hunt (`panic_hunt.rs`) covered four seams: the mtlx round-trip
parser, PSD, `.spp` and the project loader. Seven more are now covered.
Each one is driven by deterministic noise plus mutated real payloads
(xorshift, with the seed as the case id, and no new dependencies):

| Seam | Driver | Cases |
|---|---|---|
| MaterialX importer (`mtlx_import::parse_mtlx`), the third-party-document path | the 3 tracked fixtures (Blender, SP USD creator, nodedef-instanced), each first asserted to parse intact | 900 |
| `.umberbrush` presets (`BrushPreset::from_json`) | a shipped preset | 600 |
| `.umbersmart` + `.umbermask`; a template that PARSES is also APPLIED, since apply is where the values are used | the shipped worn-metal / edge-wear | 1200 |
| paint-sidecar text formats (commit, set sizes, target size, tile name, mask name) | a commit line | 600 × 5 |
| autosave journal read + REPLAY (the crash-recovery path), including newline-dense cases | noise | 200 |
| PNG + EXR readers (environment maps, stamps) | the studio PNG mutated, plus noise | 360 |
| **the JSONL agent wire** (`umber-cli agent`, a real child process) | 19 hostile-shaped steps (wrong types, NaN, 1e308, u64::MAX, 10 000-deep nesting, a 100 KB path), 150 noise lines, every truncation of a real step | ~210 |

The agent case asserts more than survival: exactly one reply per step,
each one `"ok": false` with an `error` string and the right `index`, and
a clean exit at EOF. A panic mid-session would have dropped every
following reply.

## Result

**No panic found.** Every seam answered garbage with a typed error or a
harmless success. This is evidence over these inputs, not a proof of
absence: a coverage-guided fuzzer (cargo-fuzz) would reach paths these
seeds do not. That is the follow-up, and it needs nightly and a corpus
budget.

Gate 1: umber-app 483 (panic_hunt 4 → 10), umber-cli 68. fmt and clippy
clean. The whole hunt runs in under a second, so it is cheap enough for
every CI run.

## Not covered (named)

- Mesh loaders (OBJ / FBX / glTF via `umber-mesh`). `crates/umber-mesh/tests/panic_hunt_mesh.rs`
  already exists, so this is out of scope here.
- The `.wasm` plugin loader: C2-21's consent gate now sits in front of
  it, and wasmtime's validator is upstream-fuzzed.
- `load_paint_tiles_reported` end to end needs a GPU `PaintState`. Its
  text parsers are covered above; the GPU half is the follow-up.
