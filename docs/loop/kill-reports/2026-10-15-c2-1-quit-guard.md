# Kill report: C2-1 the quit guard

Date: 2026-10-15. Author: dragon. Lock: `c2-1-quit-guard` over
`crates/umber-app/src/main.rs`, `docs/user/getting-started.md` and this
report. Source: audit C2-1 (no `close_requested` / `CancelClose` anywhere
in umber-app: closing a window with unsaved edits lost them).

## Built (`main.rs`)

- Each frame reads `viewport().close_requested()`. Every close path (the
  window's ✕, Alt+F4, the OS) arrives that way. The pure
  `quit_decision(close_requested, dirty, confirmed)` decides: a close over
  unsaved, unconfirmed edits sends `ViewportCommand::CancelClose` and
  raises the quit window. Anything else closes as before.
- The window is the File ▸ New confirm shape and reuses its keys (title,
  body, Save, Discard, Cancel), so no catalog change was needed:
  - **Save** uses Ctrl+S semantics (in place, or the dialog for a
    never-saved document) and quits only if the document is clean
    afterwards. A cancelled dialog or a failed save stays open, and the
    failure posts its sticky error.
  - **Discard** quits now.
  - **Cancel** closes the window and keeps working.
- `quit_now` sets `quit_confirmed` before sending `ViewportCommand::Close`,
  so the guard does not intercept its own close.

## Tests

`the_quit_guard_asks_only_for_unsaved_unconfirmed_closes`: dirty asks;
clean closes; a confirmed close closes; no request does nothing.
Gate 1: umber-app 512. fmt and clippy clean.

## Unverified

The viewport-command round trip (CancelClose actually keeping the window
open on X11/Wayland/Windows) is eframe's contract. No headless harness
drives a real window close. A GUI smoke on a desktop session is the
check, and it is listed for the next release smoke.

## Judgment call

The body text is File ▸ New's ("Save them first, or discard and start
fresh?"). It reads slightly off for a quit, where nothing starts fresh.
A quit-specific string lands when the catalogs are next edited.
