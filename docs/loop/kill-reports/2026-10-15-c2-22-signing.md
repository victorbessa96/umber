## Decision

Ship the alpha unsigned, documented; apply to SignPath Foundation's free
open-source signing.

The claims in `CODE_SIGNING.md` were checked against the sources:

- No networking crate anywhere: no `std::net`, ureq, reqwest or hyper in
  the sources or Cargo.lock. "No telemetry" is true.
- The installer behaviour (`~/.cargo/bin`, the PATH edit and its opt-out
  `UMBER_APP_NO_MODIFY_PATH`, the receipt) is read from cargo-dist
  0.32.0's own templates and schema in the registry.

## Next kill: `win-version-resource` (host-gated)

SignPath requires the product name and version on every signed binary.
Umber's `umber.exe` and `umber-cli.exe` carry no version resource.

- Crate: `winresource` 0.1.34 (MIT; deps `version_check`, optional
  `toml`), as a `[build-dependencies]` entry of umber-app and umber-cli.
- `build.rs`: only when `CARGO_CFG_TARGET_OS == "windows"`.
  `WindowsResource::new()` already fills ProductName, FileVersion and
  ProductVersion from Cargo's env (`CARGO_PKG_*`). Set
  `ProductName = "Umber"` explicitly, plus the app icon once a `.ico`
  exists (`assets/icons` holds SVG/atlas sources only).
- Resource compiler: windows-latest runners ship the Windows SDK
  `rc.exe` that winresource finds through the registry. Linux builds
  never call it (the target check), so CI and the host are unaffected.
- Verify: the release smoke on Windows CI. Then on the alpha's zip,
  `(Get-Item umber.exe).VersionInfo` shows `ProductName Umber,
  ProductVersion 0.1.0-alpha.1`.
- It must land BEFORE the alpha tag, or the alpha's binaries go out with
  no metadata (SignPath reviews the released form).
