# Kill report — 2026-11-10 uiux audit F11 (icon accessible names)

Lock: `razul-uiux-f11-icons-a11y`.

## What the audit found (F11)
`icons::icon_button` / `icon_button_enabled` labeled the AccessKit
Button with the raw atlas id (`"grid-3x3"`, `"sun"`, …) instead of a
localized name (`icons.rs:785-789`).

## Fix
- `icon_button` / `icon_button_enabled` now take a REQUIRED `label: &str`
  used for `WidgetInfo::labeled(WidgetType::Button, enabled, label)` —
  the atlas id can no longer drift back in as the accessible name (same
  contract shape as F8's `glyph_button`).
- All call sites pass their localized tooltip/action title:
  `toolbar.rs` (10 sites via new `rich_tooltip::action_title(action)`),
  `tool_row.rs` (`tool.tooltip`), `context_rail.rs` (`tooltip`),
  `icon_rail.rs` (`expand_tooltip` / `item.tooltip`).
- `rich_tooltip.rs` gained `pub fn action_title(action) -> String`
  (the action's localized title key through `tr`).
- Tests: icons.rs accesskit test now asserts the localized label matches
  AND the raw atlas id does not; icon_rail click test queries by the
  tooltip labels ("History", "Expand") instead of atlas ids.
