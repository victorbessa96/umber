## Built

- `parse_link_info` upgrades from a single fixed-offset heap read to
  the spec's flag-gated layout: version, flags, the optional (0x01)
  max-creation-index u32, then in order the fractal-heap address, the
  v2 b-tree name-index address (0x02), the v2 b-tree creation-order
  address (0x04). Returns `(dense, heap, btree_name, btree_corder)`
  with `resolve()`'s undefined-address semantics preserved.
- `Message::LinkInfo` carries the three addresses; the dispatch
  constructs them.
- The dense-group report branch: names each address in the note —
  `heap@0x…(fractal heap header signature "FRHP")`,
  `name-btree@0x…("BTHD")`, `order-btree@0x…("BTHD")` — through
  `probe_signature`, an 8-byte READ of each block's first four bytes
  (ASCII identity), never a walk.
- 5 tests: the full 0x07 flag layout; the no-index-field layout shift
  (heap at offset 2 — the flag gate's whole point); heap-only (dense,
  no trees); undefined-address → compact; the signature-probe contract
  on a synthetic BTHD block.

## Judgment calls

- **Probe, not walk** (the audit's own staging): the report now tells
  the v1.x follow-up WHAT sits at each address and whether it
  self-identifies (BTHD/FRHP) or is unreadable — everything the next
  kill needs to plan the real traversal, with zero speculative
  structure interpretation.
- **Flag-gated parse replaces the fixed offset-10 read**: the old
  parser hardcoded the heap at offset 10, which assumes the
  creation-index field is always present — corpus-verified behavior
  (all three real files set 0x01), but spec-fragile. The new parse is
  spec-faithful AND identical on 0x01-set messages, so the verified
  behavior is preserved where it was measured and correct everywhere
  else. Named as the one cross-check the corpus gate owes on the host.
- **`present`-style honesty in the note**: an unreadable block reports
  "unreadable", not a guessed signature.
