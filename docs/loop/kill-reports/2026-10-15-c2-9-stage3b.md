# Kill report: C2-9 stage 3b, the shell switches, saves and opens every set

Date: 2026-10-15. Author: dragon. Lock: `c2-9-stage3b` over
`crates/umber-app/src/main.rs` and this report. Follows stage 3a
(`acbb5d2`, the per-set `Document`).

## Built (`main.rs`)

- **The set switch:** after the Texture Sets panel draws, the document
  follows the paint session's active set (`doc.activate_set`). The Layers
  panel, undo and History then act on that set's own stack. The first
  activation adopts the existing stack, so a single-set session is
  unchanged.
- **The composite:** with more than one set, the frame snapshot's
  `set_layers` is filled from EVERY set's stack (stage 2's field), so each
  tile composites its own set and the inactive sets keep their planes.
  A single set leaves `set_layers` empty, the exact old path.
- **Save writes every set:** one `TextureSetLayers` per set from
  `all_sets()`. The active set keeps the import session's `TextureSet`
  (user channels); parked sets carry the default channels. The sidecar's
  orphan filter (`live`) is the UNION of every set's ids, or a multi-set
  save would have pruned the parked sets' planes.
- **Open loads every set** (`load_sets`, active = the saved active set),
  and the paint sidecar's `live` is the union, so the parked sets' planes
  load too. A single-set file still goes through `load_stack`.

## Test

`two_sets_round_trip_through_the_project_model`: a two-set document goes
through `save_to_dir` / `load_from_dir` and `load_sets`. The active set
is restored, each set holds its own layer, and ids are unique across the
reopened sets. Gate 1: umber-app 523.

## Unverified

The switch glue and the per-set snapshot fill run in `App::ui` with no

mesh, paint each, switch sets, confirm the Layers panel follows and
neither set's paint is disturbed.
