# Kill report: G5, a session log file and Help ▸ Show Log

Date: 2026-10-15. Author: dragon. Lock: `g5-show-log` over
`crates/umber-app/src/{main,logfile}.rs`, both catalogs, the GUI plan and
this report. Closes g5-menu-completion.

## Built

- **`logfile.rs`.** Every log line still goes to stderr, AND to
  `<state>/logs/umber.log`.
  - The file is truncated at launch. The previous session's log is kept
    as `umber.prev.log`, so the log of a crashed session survives the
    relaunch that reports it.
  - No new dependency: env_logger 0.11's `Target::Pipe` takes a `Tee`
    writer.
  - A file that cannot open, or a write that fails later (a full disk),
    drops back to stderr alone and never fails a log call.
- **Help ▸ Show Log** opens the file with the platform handler
  (`xdg-open` / `open` / `start`). A failure posts an error notice that
  names the path.
- Catalog keys `menu.show-log` and `menu.show-log-failed`, in both
  catalogs.

## Tests

- `the_tee_writes_both_and_survives_a_failing_file`: both sinks get the
  bytes; a broken file stops teeing and stderr still logs.
- `a_new_session_rotates_the_last_log`: session one's text moves to
  `umber.prev.log`, and the new log starts empty.
- **Real binary, ran:** a headless launch on the build host wrote the
  startup lines (starting, i18n locale, gpu backend) to
  `<state>/logs/umber.log` before the windowing failure. A headless run
  can't open a window, so exit 1 is expected there.
- Gate 1: umber-app 536. fmt and clippy clean.

## Not verified

Show Log's `xdg-open` launch needs a desktop session; on the build host it
would only spawn a handler with no display.

## Follow-up: crash reports point at the log (lock `crash-log-pointer`)

A crash report now ends with where the session log is
(`logs/umber.log`, renamed `logs/umber.prev.log` at the next launch). It
does NOT inline the log: log lines can name the user's files, and the
crash module's rule is that a report holds nothing user-supplied except
the panic text. The user decides whether to attach the log. The facts
test pins the pointer (its `ends_with` became `contains`).
