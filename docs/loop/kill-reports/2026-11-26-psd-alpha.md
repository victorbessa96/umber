# PSD straight-alpha source-over

- Lock: `razul-psd-alpha`.
- Brief: `893214f0224b` (`docs(psd): straight-alpha compositing brief`).
- Outcome: fallback compositing now uses correct straight-alpha source-over semantics, including transparent and partially transparent underlays.

## Root cause and fix

The old formula used `blended * sa + dst_rgb * (1 - sa)`, omitting destination-alpha weighting and normalization by `out_a`. The resulting straight RGB was too dark and was premultiplied again at publish.

The formula is now `(blended * sa + dst_rgb * dst_a * (1 - sa)) / out_a` for positive output coverage. Zero-coverage behavior, blend modes, and alpha rounding are unchanged.

## RED/GREEN evidence

- Before the fix, half-alpha red over transparent produced straight `[128, 0, 0, 128]`; the corrected result is `[255, 0, 0, 128]`, which premultiplies to `[128, 0, 0, 128]`.
- Before the fix, half-alpha red over half-alpha blue produced `[128, 0, 127, 192]`; the corrected normalized result is `[170, 0, 85, 192]`.
- All existing opaque and blend tests remain green.
