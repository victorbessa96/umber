# Kill report: C2-10, smart masks (`.umbermask`) apply to a layer

Date: 2026-10-15. Author: dragon. Lock: `c2-10-smart-masks` over
`crates/umber-app/src/{document,main}.rs`, the user guide and this report.
Closes C2-10's v1 scope.

## Built

- `list_smart_masks(dirs)`: the `.umbermask` twin of
  `list_smart_materials` (sorted, first directory wins, bad files skipped
  with a log line).
- `compose_smart_mask(mask, w, h, map)`: runs the preset texel by texel
  through `SmartMask::compose_scalar`, the core's pinned op semantics.
  - Generators read the red channel of the newest bake of their
    `map_name`. A missing or wrong-size map reads 0.5, a neutral mid value,
    and is reported.
  - Anchors read 1.0, fully open; they are not wired yet.
  - Constants pass through.
- Shelf: with a layer selected, each mask gets a ＋ row. It runs an
  undoable `attach_mask`, and the shell publishes the composed plane on
  every tile of the active set at that tile's size. The bakes' sRGB PNGs
  are linearized first; vector maps are already linear.
- The user guide covers smart masks.

## Tests

- `the_shipped_edge_wear_mask_composes_from_curvature`:
  - flat curvature closes the mask (0) and sharp curvature opens it (255);
  - a missing map reads neutral (≈ 230 via levels) and is reported;
  - a wrong-size map counts as missing.
- **Mutation check:** every texel reading texel 0 fails it.
- Gate 1: umber-app 529. fmt and clippy clean.

## Not covered by tests

- Undoing the attach removes the mask, but the published pixels are not
  journaled. A re-attach starts white, per the existing detach rule, so
  nothing stale shows.
- The shell's per-tile publish runs in `App::ui` and has no harness.
