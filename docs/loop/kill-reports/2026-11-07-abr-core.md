## What landed

`crates/umber-brush/src/abr.rs`: a clean-room reader for the `samp`
sections of v6/v7 `.abr` files — the 8BIM section walk, the per-brush
record (Pascal name, the skipped parameter block, bounds, bit depth,
compression, the alpha plane), 8-bit raw / 8-bit RLE (PackBits) / 16-bit
raw planes, and named errors for every refusal. `pub mod abr;` is wired
into `umber-brush`.

## The dragon's corrections to the claw's work (and to the brief)

1. **The brief's premise was wrong and the claw said so.** The brief
   told the claw to read diameter/hardness/spacing "from the brush
   header" after the stamp. The vendored reference
   (`docs/claw-artifacts/ag-psd/src-tree/src/abr.rs`) shows there is no
   such block: the per-brush bytes between the name and the bounds are
   PADDING the reference skips without naming, and the brush's real
   settings live in the descriptor (`desc`) sections (the reference
   reads `Spcn`, `Hrdn`, `Diameter` from the descriptor tree). The claw
   read the padding anyway (following the brief) and flagged it as its
   assumption #2. **The fields were REMOVED** from `AbrBrush`: publishing
   padding bytes as a brush's diameter/hardness/spacing would report
   numbers that are not the brush's. The block is now skipped, never
   interpreted, and the descriptor wave is the named follow-up.
2. **A total-plane budget was added.** The per-stamp cap alone allowed
   4096 stamps x 16 MiB = 64 GiB of decoded planes out of a small
   hostile file. `MAX_TOTAL_ALPHA_BYTES` (256 MiB) now caps the SUM, with
   the `AbrError::TooMuchData` variant and a pin
   (`total_data_budget_refuses_the_sum`).
3. **The clippy `manual_is_multiple_of` class was fixed** (three
   `while body.len() % 4 != 0` sites).
4. **The pins that asserted the fabricated parameters were rewritten**:
   `parameter_block_is_skipped_not_interpreted` (the stamp is exact; a
   file whose block holds different bytes parses to the same stamp) and
   the v6.2 pin now asserts the stamp only.

## Pins (18 from the claw, 2 rewritten, 1 added)

The required set: the synthetic v6 brush byte-for-byte; the PackBits
literal+repeat fixture (`[2,1,2,3,0xFE,9]` → `[1,2,3,9,9,9]`); the
parameter-block pin (rewritten); wrong magic → `NotAbr`; truncated alpha
→ `Malformed`; an oversized stamp → `StampTooLarge` BEFORE the plane is
allocated; a v8 descriptor-only file → `UnsupportedVersion`. Plus the
claw's extras (v1/v2/v5 refusals, unknown minor version, raw and 16-bit
planes, PackBits 128 no-op, `desc` section skipping, the brush-count cap,
v6.2's wider block, v7 acceptance, the zero-length record) and the
dragon's total-budget pin.

## Not done (named follow-ups)

- **The descriptor wave**: the `desc` sections carry diameter,
  hardness, spacing, angle, dynamics and the tip shape. Until that wave
  lands, an imported brush has a stamp but no settings.
- **The mapping wave**: `.abr` stamp → `.umberbrush` + `<stem>.stamp.png`
  sidecar (the row-267 brief's mapping table), and the CLI's
  `--kind brush` acceptance of `.abr` (a multi-preset fan-out).
- **A real-file fixture**: the synthetic fixtures pin the format's
  structure as the vendored reference describes it; no real `.abr` file
  has been parsed yet (the vendored reference is the only witness). A
  real-file check is the first task of the mapping wave.
