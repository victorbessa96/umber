## Judgment calls

1. **Dirty check skipped (named follow-up).** Grep confirms the repo has no modal
   pattern — the only `egui::Window` is the Perf HUD (`main.rs`). v1 discards
   unsaved work without asking, consistent with File > Open Project, which
   already loads without a confirm. A half-modal would be worse than none.
   Recorded in `reset_for_new`'s + `new_project`'s module docs.
2. **Environment kept.** `set_environment` is never called; a loaded IBL stays
   bound. An IBL is a studio asset, not document state. Same for the camera.
3. **Paint session rebuilt, not cleared.** There is no "clear all tiles" API that
   restores the boot shape (default set + channel stack, empty stroke history,
   fresh masks); a fresh `PaintState::new` on the same device/queue is exactly
   what `UmberApp::new` builds, so the mirror is the lowest-risk reset.
   Feature-missing devices degrade to `None` with a warn, same as boot.
4. **Mesh, graph, fill/path/bake/export states kept.** The brief's reset list is
   implemented exactly. Mesh: `Viewport` has no unload path — clearing
   `state.mesh` alone would leave a ghost mesh on screen. Graph: `GraphPanel`
   plugin paths load at construction; a reset without them would silently drop
   plugins. Fill caches are keyed by layer id and sit unused once their layers
   are gone — the same shape as deleting a layer today. All recorded in
   `reset_for_new`'s boundary note; a fuller studio-reset is follow-up work.
5. **No shortcut.** Ctrl+N stays unbound (SHORTCUT_KEYS untouched; the 6+4
   binding census still holds). Pinned by test.
6. **`shell.new-deferred` left in place** per the NEW-KEYS-ONLY amendment; the
   dragon prunes. The toolbar no longer references it, so the i18n completeness
   test (en-US must contain every called key) is unaffected — unused keys are
   not flagged.
7. **File menu row added.** The kill title is "File > New" and the menu had no
   New entry; one row pushing through the shared `actions` vec, same as Open Mesh.
