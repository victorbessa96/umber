# Kill report: the Bakes panel's four untranslated map labels (C2-29's tail)

Date: 2026-10-16. Author: dragon. Lock: `bakes-map-i18n`
(`crates/umber-app/src/bakes_panel.rs`, both catalogs, this report).
C2 audit row 29's remainder — the bake kinds themselves were already
landed (BakeSelection carries 8 + Height; the row's "4 of 9" was stale
doc drift), and this kill closes the row's leftover: four map labels
rendered as raw English strings instead of catalog keys.

## Built

- Both catalogs gain `bakes.map-world-normal`, `bakes.map-id`,
  `bakes.map-bent-normal`, `bakes.map-height-transfer`
  (pt-BR: "Normal em espaço de mundo", "ID", "Normal dobrada",
  "Altura (transferência da malha alta)") — key parity holds.
- `BakeSelection::label()`: WorldNormal/Id/BentNormal/Height now go
  through `tr()` with the new keys. Height moves off
  `viewmode.height` to the transfer key: the High-poly group's height
  IS the transfer output, and the label should name the thing it bakes.
  The old comment ("untranslated until the catalogs ... take the keys")
  is gone with the debt it described.
- `bakes.map-height-transfer` was added alongside, used by the panel —
  the completeness test pins existence, and the retired raw strings
  left no orphans.

## Judgment calls

- Kept `viewmode.normal` for the tangent-space Normal label: it
  duplicates the view-mode's existing "Normal" string and renaming
  would touch the view-mode keys for zero user value.
- Height: chose the precise transfer label over the shared channel
  name. If a painter later wants the paintable-height label here, that
  is a UX call with Bessa, not a doc debt.

## Unverified

- The four strings' pt-BR wording is mine; a native review pass
  (ROADMAP `wave-i18n-audit`) is the standing quality gate for that.

## Deferred

- None. The audit row ticks fully closed with this kill.
