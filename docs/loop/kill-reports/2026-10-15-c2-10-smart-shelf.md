# Kill report: C2-10 the smart-material shelf

Date: 2026-10-15. Author: dragon. Lock: `c2-10-smart-shelf` over
`crates/umber-app/src/document.rs` and this report. Source:
`docs/loop/audit-2026-10-15-c2.md` C2-10. The core loader and two shipped
materials (`assets/smart/worn-metal.umbersmart`, `painted-wood.umbersmart`)
existed. No app code read them.

## Built (`document.rs`)

- `smart_dirs()` looks in the repo's `assets/smart` and in `smart/`
  beside the binary, the same two-place rule as the i18n catalogs.
- `list_smart_materials(dirs)` returns every loadable `.umbersmart`,
  sorted by display name and deduplicated by file name. A broken file
  is skipped with a log line, never a panic or a broken row.
- **`apply_smart_material(doc, material)` runs one undoable command per
  template field:** add, then opacity, blend and mask when they differ
  from a fresh layer. `SmartMaterial::apply` in core writes the stack
  DIRECTLY, bypassing history and the autosave journal. A shelf built on
  it would have created layers Ctrl+Z could not remove and a crash would
  have lost.
- `smart_shelf_ui` is a collapsed section at the top of the Layers panel.
  It holds one row per material with ＋ Apply, which selects the top new
  layer, and ⟳ to rescan. The list is cached in egui memory, not read
  from disk every frame.

## Tests (2)

- `the_shipped_smart_materials_list_and_apply_undoably`: both shipped
  materials list. Painted wood applies with every template field on its
  layer (name, opacity, blend, mask), and undoing every new history
  entry leaves the stack EMPTY.
- `a_broken_smart_file_is_skipped_not_fatal`: a malformed file and a
  non-`.umbersmart` file are ignored, a good one lists, and two
  directories with the same file name do not duplicate it.
- Gate 1 (umber-app): fmt, clippy (one `cloned_ref_to_slice_refs` in the
  test, fixed), 474 tests.

## What this does NOT do yet

- **Generator bindings are not wired.** A template fill's
  `mesh_map_generator` binding (AO, curvature, position) is what makes a
  smart material "smart". The layers arrive with their structure, but
  each fill needs its generator graph connected. That is the follow-up
  and the next real step for C2-10.
- **No smart masks on the shelf.** `.umbermask` (edge-wear) needs a mask
  target to apply to, which is the mask-stack-with-effects work from
  requirements §2.
- No thumbnails and no drag onto the mesh. Labels are the materials'
  own names, and the section header reuses the material-layer key plus
  the file extension (the catalogs are under a sibling lock).
