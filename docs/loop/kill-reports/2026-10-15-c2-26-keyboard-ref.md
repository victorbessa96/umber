# Kill report: C2-26 the generated keyboard reference

Date: 2026-10-15. Author: dragon. Lock: `c2-26-keyboard-ref` over
`crates/umber-app/src/actions.rs`, `docs/user/keyboard.md` and this
report. Source: audit C2-26, the "generated keyboard reference" half.

## Built

- `actions::keyboard_reference()` generates `docs/user/keyboard.md` from
  `BINDINGS`, the same table the shortcut poll and the menus read. Each
  row gives:
  - both platform spellings (egui's own formatter, with `[`, `]` and `,`
    printed as key caps rather than egui's off-mac names);
  - the action;
  - where it fires, derived from `Focus::allows`, so the doc states the
    real typing rule ("not while typing in a field" vs "everywhere, even
    while typing", and Tab: "nothing focused").
- `keyboard_reference_is_current` regenerates the reference and compares
  it with the committed file. A key added or changed without
  regenerating fails the suite. `UMBER_REGEN_KEYBOARD_DOC=1` rewrites
  the file.
- `every_binding_has_reference_text`: an action bound without a
  reference line fails.

The 24 rows match `BINDINGS` exactly. F3 and Ctrl+Shift+P both open the
palette, and both rows are listed.

Gate 1: umber-app 485. fmt and clippy clean. The generator is
`cfg_attr(not(test), allow(dead_code))`, since only its test calls it.

## Judgment calls

- **English reference text, not catalog keys.** The reference is a
  repository document; the UI's labels stay the catalogs' job, and the
  catalogs are under a sibling lock anyway.
- **Generated by a test, not build.rs.** Writing into `docs/` from a
  build script would dirty the tree on every build. The test is the
  drift gate, and regeneration is explicit.
