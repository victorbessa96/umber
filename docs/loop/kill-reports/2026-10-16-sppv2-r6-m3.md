## Built

- `hdf5.rs`:
  - `Message::Attribute` gains `m3: Option<[u8; 16]>`;
    `parse_attribute` (renamed from `parse_attribute_name`) decodes the
    attribute message v1 layout — the value rides after the 8-padded
    name, datatype message, and dataspace message — and extracts the
    16-byte checksum when the name is `m3_x64_128`.
  - `RawDataset.m3: Option<[u8; 16]>` threaded through the decode loop.
  - `murmur3_x64_128(data, seed)`: a straight port of the canonical
    public-domain reference — wrapping u64 ops, the exact constants
    (C1/C2, the block/tail mixing, fmix64). NO external hash crate:
    the dependency lock stays untouched.
  - `m3_verifies(&RawDataset) -> Option<bool>`: `None` = no stored
    checksum (unverified), `Some(false)` = MISMATCH.
- `model.rs`: the dataset report line upgrades from `m3=yes|no` to
  the real state — `verified` / `MISMATCH` / `present` (hash seen but
  no value decoded) / `no`.

## Judgment calls

- **Report-only on mismatch** (the audit's own contract): a corrupted
  or editor-mismatched dataset still opens, with `MISMATCH` in the
  report — verification is information for the import audit, not a
  gate that refuses files. The corpus gate (host-side) reads the
  report line.
- **Hand-rolled MurmurHash3** over a dependency: the algorithm is 60
  lines of wrapping arithmetic, the reference port is public-domain,
  and pinning it with external vectors is stronger than trusting a
  crate's version drift. The corpus files carry the ultimate oracle.
- **`present` as a distinct state**: a `m3_x64_128` attribute whose
  value fails to decode (message truncated) is reported as present-
  but-unverified — never conflated with a verified hash or a missing
  one.
