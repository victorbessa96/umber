## Built

- `first_run.rs` (new):
  - `should_show()`: true while the preferences file does not exist —
    the "never chose anything" signal. Finish (and Skip) both write
    the file, so the window shows exactly once.
  - `QuickSetup`: open/is_open state; `show(ctx, stylus, prefs)` draws
    the window and returns `FinishedSetup` on Finish/Skip.
  - `SetupTheme { FollowOs, Light, Dark }` → `egui::ThemePreference`
    (None = follow the OS).
  - The five sections: language (the locale combo over
    `i18n::with(|i| ..)` — the thread's own state, the same
    `set_locale_persisted` path Preferences uses, so the window's own
    labels re-localize the frame after a switch); theme combo;
    navigation combo over `NavPreset::ALL` with the Preferences
    window's own `prefs.nav-*` keys (no second label source); keymap
    preset combo (Umber / Blender-like, the keymap editor's own
    keys); tablet check (StylusPoller::hovering + live pressure,
    SUCCESS-tinted when a pen is up, an honest "no pen" line when not).
  - Tests: `should_show_is_true_only_without_a_prefs_file` (writes a
    probe prefs file and requires the window NOT to show with it
    present — the contract, not the machine's state);
    `theme_choices_map_to_egui_preferences`;
    `the_setup_window_round_trips_open_state`.
- `main.rs`:
  - `mod first_run;` + the `quick_setup` field, opened at construction
    when `should_show()` (the first launch).
  - The draw block after `show_preferences`: on Finish — write
    `prefs.nav`, save the preferences (which also records the current
    keymap line — the file-existence flag the window gates on), set
    the egui theme when a forced one was chosen, install the
    Blender-like keymap overrides through the keymap editor's own
    `KeymapPreset::overrides()` + `actions::set_overrides` + the
    persisted line, and adopt the nav preset immediately through the
    same `set_nav_preset` call the Preferences combo makes.
  - Help ▸ Quick Setup row (`setup.title`) re-opens the window.
- i18n: `setup.title/intro/language/theme/navigation/keymap/tablet/
  tablet-live/tablet-pressure/tablet-none/finish/skip` in BOTH
  catalogs (13 keys; en-US + pt-BR, native-order sections).

## Judgment calls

- **Prefs-file existence as the first-run signal**: the simplest
  honest oracle — the file is written by Finish, Skip, AND any
  Preferences edit, so a user who opens Preferences once never sees
  Quick Setup either. Rejected: a dedicated marker file (a second
  source of truth for "has chosen").
- **Skip still writes the file** (with the current prefs' nav, the
  default theme, no keymap change): the window must not haunt the
  user every launch. Skip = "accept defaults", not "ask again".
- **The tablet check is informational, not a blocker** (B:A9.2's
  "tablet check"): a failed check never blocks Finish — Painter's own
  first-run does the same.
- **Theme via `ctx.set_theme`** at apply time (not a persisted
  preference): egui's OS-follow is the default and this window only
  FORCES a branch when the user picks Light/Dark; a persisted theme
  preference is the g7-density-scale/preferences row's surface, not
  this kill's.
- **The language picker reads `i18n::with`** instead of taking an
  `I18n` param: the app holds no i18n state (it is thread-local by
  design — i18n.rs), and the first draft's `&mut I18n` param had no
  real argument to receive.
