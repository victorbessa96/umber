## What landed

- **Kill 1:** new `crates/umber-mesh/src/uv_gbuffer.rs`, the one CPU
  UV -> (triangle, barycentrics) primitive:
  - `UV_DET_EPS = 1e-10`, `UV_BARY_EPS = 1e-6` (public so the WGSL bake
    shaders can quote them in kill 4);
  - `UvHit { triangle, bary: [f32; 3] }`, `UvTri` (prepared footprint:
    `of`, `from_uvs`, `bary`, `bounds`);
  - `uv_to_barycentric(mesh, uv)` (last-in-index-order wins, never panics);
  - `UvGBuffer::build(mesh, tile, w, h)` + `at` + `covered()` (the shape
    export padding's dilation consumes);
  - shared helpers `lerp3`, `tile_offset`, `texel_center_uv`,
    `texel_window` so culling and coverage cannot disagree.
  - Re-exported from `umber_mesh` (`lerp3, uv_to_barycentric, UvGBuffer,
    UvHit, UvTri, UV_BARY_EPS, UV_DET_EPS`).
- **Kill 2:** S1 `fill::rasterize_uv_geometry` and S2
  `polygon_fill::uv_triangle_at` now delegate to the primitive. The edge
  functions, the `-e_i / area` sign correction, the bbox window, the texel
  center formula and the position interpolation order (`p0*b0 + p1*b1 +
  p2*b2`) are byte-for-byte the old expressions moved into one place, so
  output is unchanged apart from the epsilon below. `fill::uv_finite` was
  deleted as dead code. Net: −106 / +24 lines in fill.rs + polygon_fill.rs.

- **Kill 3:** Axis B consolidation. `raycast::uv_at` routes through the
  new `uv_gbuffer::lerp2`, `Cage::lerp_at` through `lerp3`. IEEE `*` is
  commutative and the summation order (vertex 0, 1, 2) is unchanged, so
  both are bit-identical. The ray axis itself (Möller–Trumbore) is a
  non-goal and untouched.
- **WGSL eps pin (kill 4 groundwork):** new `#[cfg(test)] mod
  uv_eps_parity` in `crates/umber-gpu/src/bake_shaders.rs` parses the
  `DET_EPS`/`BARY_EPS` and `ID_DET_EPS`/`ID_BARY_EPS` literals out of
  `POSITION_BAKE_SHADER` and `ID_BAKE_SHADER` and asserts them equal to
  `umber_mesh::UV_DET_EPS`/`UV_BARY_EPS`. Before this, the CPU/GPU
  epsilon divergence (`1e-12` vs `1e-10`) had no test to catch it.

## The one intentional behavior change

The CPU degenerate threshold moves from `1e-12` to `1e-10`, matching the
GPU position/ID bakes. Footprints with `1e-12 <= |area| < 1e-10` (under
~1.4e-5 UV units across, smaller than one texel at every supported
resolution) used to be filled on the CPU and skipped by the GPU bakes.
Now both skip them. Pinned by `det_eps_boundary_is_1e_10`.
