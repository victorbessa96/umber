## Design rules (bind every wave)

1. **Painter muscle memory wins defaults; Blender supplies interaction
   grammar; photocraft supplies the egui technique.** Umber's users come
   from Painter (brief). Where Painter and Blender differ, the default is
   Painter's and Blender's is a preset (navigation, keymap).
2. **One action table.** Menus, toolbar, shortcuts, the command palette, the
   keymap editor and the status-bar hints all read ONE registry of
   `ActionId → {label key, default binding, enabled-reason}`. A shortcut
   printed next to a menu item is the one that fires [PC:#3, PC:#12, B:D20].
3. **Every user string through `tr()`, both catalogs** (CLAUDE.md rule 7).
4. **Every new widget publishes AccessKit info** (`resp.widget_info(..)`)
   [PC:#18]. It makes the widget screen-reader visible AND queryable by
   kittest, which is how GUI kills get behaviour tests, not only pixels.
5. **Every GUI kill ships a test.**
   - Pure logic (scoring, layout math, binding resolution): a unit test.
   - A panel or widget: a kittest behaviour test through AccessKit roles,
     and a snapshot where the look IS the contract.
   - Port photocraft's harness patterns in wave G0: the fonts gate, the
     fixed step dt, theme sweeps [PC:#19].
6. **Reactive repaint.** Timers use `request_repaint_after`, never
   continuous repaint while idle [PC: techniques].
7. **Reduce Motion gates all motion**, and the tooltip-off switch gates all
   tooltips [B:F15, PC:#10].
8. **Destructive = confirm; slow = labelled** [P:E, B:E10].

## The waves

Waves are ordered by adoption value: what a Painter user hits in the first
five minutes comes first. Each kill names its file surface, so kills inside
a wave run in parallel under kill locks.

Shared files:
- `main.rs` is shared by many kills. Each kill touches only its own
  call-site block, and the wave's integration commit lands them together.
- The i18n catalogs (`assets/i18n/*.ftl`) are always appended by one kill
  per wave: the wave's "i18n owner" lists the keys the others need.

## Verification contract per wave

- Gate 1: `scripts/wave-battery.sh umber-gui umber-app` (+ touched crates),
  which includes the kittest suites.
- Snapshots: the wave's snapshot PNGs are committed. CI compares them.
  `UPDATE_SNAPSHOTS=true` regenerates them locally ONLY when the kill
  intends the visual change, and the kill report says so.
- Gate 2: one push + one CI run per wave.
- Each wave closes with a short `docs/loop/kill-reports/` entry per kill.
  This plan's wave table gets a ✓ and the commit SHA.
